# Round 546 - egress pass 5: Task Table + Auth check

Measured (22 Oct): Task Table loaded the releases table four separate times (~330 kB), each time keeping only the releases isRecent() accepts; Auth egress was ~31 MB/day (12.8% of all egress).

## Task Table (app/task-table/page.js) - no function change
- ONE shared request (loadRecentReleases) now fetches only the releases the page keeps anyway - undated, or dated on/after TASK_TABLE_CUTOFF (2026-07-01), done in the query via .or("release_date.is.null,release_date.gte.<cutoff>") - with the union of the columns the consumers read. Upload counts (requested = true), confirm phase 1/2, pre-release, and the subteam "Du An" count all read that one list; the per-subteam Booking lookup now finds its releases in the same list instead of querying again.
- The YouTube Ads subteam lookup keeps its own query (it must cover old releases too, a recent ticket can point at an old DID) but only selects did + tags and skips releases with no did/tags (they can never carry a subteam).
- Every consumer sees the same rows after isRecent() as before, and every column its done-rule reads is in the list (checked against lib/workstationDoneRules.js, releaseLabel, effectiveSubteamTags). Side effect: the upload query is no longer subject to PostgREST's 1000-row cap.
- Not changed: the per-ticket-type tickets queries (they carry the `data` JSON, which many parts read).

## Auth check (lib/AuthContext.js)
- The once-a-minute getUser() (which makes kicks take effect) ran in EVERY open tab, even hidden ones. Hidden tabs now skip it, and a tab runs one check the moment it becomes visible again (throttled to once per 15 s). A visible tab is still checked every minute, so a kick still takes effect within a minute of anyone actually using the app.

## Report page - left as is
Already pruned to 29 columns in Round 150 (163 kB for ~1000 releases, all-time charts). Cutting it further needs server-side aggregation of every chart + isReleaseDone, i.e. a bigger rewrite with real risk to the numbers; not worth it for ~160 kB per Report visit unless egress is still a problem after the other rounds.

Re-measure: Task Table with DevTools (supabase.co/rest, sort by Size) - expect the 5 releases requests (77/75/66/60/55 kB) to become 1 + 1 small. Auth: Usage > Egress tooltip over the next days - the Auth slice should shrink.
