# Round 524 — freeze package terms at lock + Config price/terms warning + change log

## Decision (user)
Freeze locked packages now; warn clearly when someone edits Config prices/terms.

## What is frozen
- Prices: lines already store their own unit_price/amount (verified: 0 of 2,096 lines changed after the 5 Oct config save). New: a locked release's blank-price line no longer pulls today's Config default on re-Summarize (media-booking page, both normal and YouTube Ads backfill).
- Terms: NEW media_booking_packages.frozen_terms (jsonb) + frozen_at = copy of the tier's terms_text, tro_gia_booking_text, shared blocks A/conditions/B and the Trợ Giá items, taken when the release is locked. The artist link reads: per-package override > frozen copy > live Config. Shared blocks and Trợ Giá items follow the picked package's frozen copy.
- Done by DB triggers, so every lock path (artist link, staff toggle, simulator, SQL) freezes: releases.package_locked false->true, and a package created on an already-locked release. Only empty frozen_terms are filled: unlock/relock never refreshes an old freeze.
- Backfill in the SQL: every release locked right now is frozen with today's Config text.

## Warning + log
- Config -> Media Booking Pricing (category, Ads, add-on defaults), Package Terms (per tier terms, Trợ Giá text, shared blocks A/conditions/B) and Trợ Giá Booking list: any change now shows a confirm dialog explaining what it does and does not reach; Cancel reverts the field. Unchanged values do not prompt.
- NEW config_change_log (old/new value, actor, time) filled by DB triggers on global_settings (price defaults, package terms keys, trợ giá items) and contract_type_packages. Staff can read it.
- Round 509's package_change_log now ignores frozen_terms/frozen_at, so the freeze is not flagged as an unexpected artist_guest write.
