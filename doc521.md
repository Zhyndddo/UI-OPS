# Round 521 — artists couldn't create tickets (notification trigger permission)
Cause (confirmed by running as the `anon` role): `trg_notify_on_ticket_insert` -> notify_on_ticket_insert() -> fanout_notification() ran with the caller's permissions; anon has no INSERT on `notifications`, so the whole ticket INSERT rolled back with "permission denied for table notifications". The app never checks the insert error, so a real artist's package pick left no Phụ Lục ticket (TMNX-20102026-0163; the 17 staff picks in the same window all got theirs). The artist-side rpc("fanout_notification") in pick-package was failing the same way.
Fix (sql/pending/fix-round521-anon-ticket-insert-notifications.sql): the 5 notification functions become SECURITY DEFINER (search_path=public); notify_profiles (trigger-only helper) is no longer executable by anon/authenticated; fanout_notification stays callable (the app uses rpc). No grant of INSERT on notifications to anon. Tested on a scratch Postgres: reproduces the exact error before, passes after, re-runnable.
