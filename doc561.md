# Round 561 — kworb Vietnam Spotify crawl (Milestone -> "Spotify VN")

Source: https://kworb.net/spotify/country/vn_daily_totals.html (plain HTML table). Runs daily at 04:00 UTC = 11:00 Vietnam (vercel.json cron "0 4 * * *" -> /api/cron/kworb-vn; Vercel Hobby only allows daily crons) and on the "Refresh now" button (dev / OPS only).

## What it keeps
Only two kinds of track (everything else on the chart is ignored, not stored):
1. OURS — title matches a release title / release track name AND an artist matches that release's artists. Gets daily snapshots (Total, Days, Peak...). Daily streams = change in Total between the two newest chart dates; 7-day = vs the snapshot 7+ days earlier.
2. SUSPECT — (a) same title as one of our releases but a different artist, or (b) one of our artists (releases, tracks, artists table; aliases in brackets count) with a title we do not have. Listed in the "Review suspects" popup: Follow up / Dismiss / Undo, remembered per track (a dismissed track is not re-flagged).
Matching ignores accents, case, punctuation, "(feat ...)" / "[Remix]" parts, and artist separators (, & x feat ft with +). Titles/artists shorter than 3 characters are never matched.

## Run order
1. Run add-round561-kworb-vn.sql (creates kworb_vn_tracks, kworb_vn_snapshots).
2. Push the code (adds the cron; Vercel registers it on deploy). For 12-hourly runs see optional-round561-kworb-12h-pgcron.sql (Supabase pg_cron calls the same route).
3. Milestone -> Spotify VN -> "Refresh now". Check: rows read ~287, ours > 0. If it says "Parsed only N rows", kworb's layout differs from what I coded -> send me the error.

## Known limits
- Parser written from the page's described structure and tested on a sample, NOT on the live HTML (my fetch tool could not load it raw). First real run is the real test.
- kworb updates once a day, so two runs a day normally give the same chart date (the second just overwrites the first).
- kworb totals exclude time spent outside the daily chart; a song that leaves and re-enters shows a gap.
- Be polite: 1-2 requests a day, User-Agent names VIEENT + tech-service-group@vieent.com. Check kworb's terms before relying on it.
