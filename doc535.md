# Round 535 (zip 1 of the anchor cycle) — Viral Posts: tracks without a DID + Platform/Channel reference selects

## What changed (Milestone workstation → Viral Posts tab)
1. **Track without a DID (team leaders and above only).** In "Log Viral Posts", a team lead can save a track that isn't matched to any release: whatever is typed in Release Name / Artist / DID is saved as-is, no DID check (an amber note says so). If an exact DID is typed it still auto-matches the release as before. Others (non-team-lead) still need a matched release, unchanged.
   Those rows have release_id = null and show in a new table under the main one: "Tracks without a matched release" (track, artist · typed DID, channel : url; best snapshot per url). Team leads can click a row to add another snapshot; everyone who sees the tab can read the table. They also appear in the Log tab's search (it matches on title/artist text). They do NOT appear on any release's media-report magic link (no release to attach to).
   New rows now also record created_by (who logged it).
2. **Platform and Channel are select-from-list fields** (type to filter, click to pick). Unmatched typed text is dropped when you click away; use the "+ Add …" row to create.
   - Platform list = TikTok / Facebook / Instagram / YouTube / Thread + any platform already in Booking Channels + platforms added here. Adding a platform that isn't in the list saves it to its OWN table (viral_post_platforms), used only by this field.
   - Channel list = channels of the chosen platform (Booking Channels reference + custom ones). Channel is disabled until a platform is picked; changing the platform clears the channel.
   - "+ Add channel": for a platform Booking Channels already knows, the channel is added to booking_channels (type Direct, no brand/group — complete it on Booking Channels if needed). For a custom platform it goes to viral_post_channels (never touches booking_channels).
3. **Backup gap closed:** scripts/backup.js now also backs up milestone_viral_posts (it was missing) plus the two new tables (optional).

## SQL (run before using it)
