# Round 525 — Re-Check smartlink tab: manually added row not showing; backup gaps

## Smartlink tab (Confirm / Re-Check workstation, Phase 2)
Symptom: a phái sinh smartlink added by hand ("Manual", no ticket) did not show; ones from a ticket did.
Cause: the merged Phase 2 table sorts by release date, newest first. A ticket row borrows its date from the ticket; a manual row has no ticket and (unless its DID matches a release) no date, so it counted as the oldest possible and sorted to the very last page. It was saved; it was just not on page 1.
Fix (app/workstation/confirm/page.js): rows are ordered by a separate _sort_date = ticket date, else the matching release's date, else when the row was added. The Date text still reads "no date"; the row highlight is unchanged. The release rows get _sort_date = their release date, so nothing else moves. Phase 1 is unchanged.

## Backup gaps found while checking
phai_sinh_smartlinks, media_booking_channel_status and media_booking_package_entry_snapshots were not in the backup at all (the Booking Board Done/Not Done status and the smartlink rows could not have been restored). scripts/backup.js now includes them plus config_change_log, all as OPTIONAL tables (skipped, not fatal, if a table is missing).
