# Round 577 — Full catalog (daily track report) + stricter kworb matching + "Not ours"

## Do in this order
1. Supabase SQL editor: run `sql/pending/add-round577-full-catalog.sql` (after the 561 / 563 / 565 kworb SQL). Idempotent.
2. Push: `git add -A` / `git commit -m "Round 577: Full catalog + kworb strict match + Not ours"` / `git push`. (Round 576 Ma Sói files are in the same folder; they go out with this push.)
3. Sidebar -> FULL CATALOG (dev only) -> choose the track report CSV (ProductTrack_report) -> it shows new / changed / removed -> "Update the catalog". First upload sends everything (~46 MB, a couple of minutes); later days send only the differences.
4. Then Milestone -> Spotify VN -> "Test parse" and "Refresh now". The result line now ends with "full catalog N tracks (uploaded X h ago)".

## Daily routine
Upload the new track report before 11:00 Vietnam time (the kworb cron runs 04:00 UTC). If the catalog is more than 36 h old the run still happens, with an "OLD, upload today's file" warning (skipping would lose that day's chart data).

## What a "hit" means now
- Track name: cleaned (accents, case, "(feat …)", "[Remix]", " - suffix" removed) and EQUAL. For singles the report leaves Title empty, so the product title is the track name.
- Artist: the chart row's FIRST artist is one of the track's artists (main or featured), OR every main artist of the track is listed on the chart row. Someone merely sharing a featured guest no longer matches.
- Catalog titles are used for "ours" only. The "same title, different artist" suspect list still comes only from releases in the app (115k catalog titles would flood it).

## "Not ours"
Button on every row of Spotify and YouTube ours lists. It marks the kworb id as dismissed (existing trigger -> kworb_vn_ignored), so the crawler skips it for good. Review suspects -> Dismissed tab lists them with Undo.

## How it stays light
Each track stores a cleaned title key + row hash. The page downloads id + hash (~4 MB), sends only new/changed tracks, deletes tracks that left the report. The kworb run asks the database only for catalog tracks whose title key appears on that day's chart pages (Spotify) or inside a video title (SQL function kworb_catalog_in_text), never the whole catalog.
