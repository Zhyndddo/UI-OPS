# Round 569 — Tools -> "Picture render" (names onto a picture, download + Drive)

No SQL. Nothing is stored in the database. Admin and dev only (tab hidden for others; the server checks the role too).

## Run order
1. Apps Script: paste `drive-webhook-v3.gs` over your script (KEEP your own SECRET + FOLDER_ID), Deploy > Manage deployments > pencil > New version > Deploy. (v3 includes v2's big-file upload from Round 568; it adds sub-folders for this tab. The first v2/v3 deploy asks for one extra permission.) Without v3 the pictures still save, but into the main Drive folder instead of picture-render/invitation.
2. Push this zip. No new env vars (it reuses HALLOWEEN_DRIVE_WEBHOOK_URL / HALLOWEEN_DRIVE_SECRET).
3. Open Tools Directory -> tab "Picture render". It shows a grey PLACEHOLDER picture with a dashed box where the name goes. Type a few names (one per line), keep "Also save to Google Drive" ticked, press Render.
   - 1 name = one PNG download; several = one zip. Each picture also lands in Drive: <your folder>/picture-render/invitation/.
4. Check the Drive folder, and the list under the button (✅ rendered, "Drive ✓" saved; a "Drive ✗" line shows why).

## When you send the real picture
Send: the picture (PNG/JPG), the font file (.ttf/.otf, must include Vietnamese letters if names have them), the text colour (hex if you have it), and where the name goes (roughly, e.g. "centred, a bit below the middle", or a screenshot with the spot marked) plus the biggest name width you expect. I then set in lib/pictureRenderConfig.js: src, font, text.x / y, align, maxWidth, fontSize, color. A long name shrinks to fit the width; position never moves.

## Limits
- Up to 200 names per batch. Duplicate names in the list are merged.
- Drive upload goes through the server: one picture up to 4.4 MB (PNG; a bigger one is saved as JPEG; still too big = download only). The download is always the full PNG.
- Same name rendered again = a second file in Drive (nothing is overwritten or deleted).
