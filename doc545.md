# Round 545 - egress pass 4: Booking Board loads link text on demand

Measured (22 Oct): Booking Board downloaded media_booking_entries for the 50 releases on the page in 2 paged requests (~89 kB each) including every link's URL text, although links are only shown when a cell is expanded, in the Add Link popup, or in a hover tooltip.

Change (app/booking/page.js only, no SQL):
- loadPage() no longer selects `link` for media_booking_entries.
- New ensureLinks(entries): fetches `id, link` for just those entries (100 ids per request) and merges them into state; ids already requested are skipped; the "already requested" set resets whenever the page's entries are reloaded.
- BrandCell calls it when its cell is expanded or its Add Link popup is open, and on hover over the cell count (so the tooltip gets the links too). Until loaded, a row shows "loading..." instead of the URL, and the hover tooltip lists status only.
- Works in both the table and the mobile card view (same BrandCell). New/edited links come back from their own insert/update so nothing else changes. CSV export has its own full fetch and is unchanged.

Expected saving: the link text is a third to a half of those rows; I have not measured it - re-measure in DevTools (supabase.co/rest filter, sort by Size): the two ~89 kB media_booking_entries requests should be clearly smaller. A new small request (select id,link ... in id) appears when you expand/hover a cell.

Numbering: 544 stays reserved for the full-repo anchor zip.
